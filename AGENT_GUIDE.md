## 1. System Overview & Process Topology

This system is an automated, real-time Virtual Football League (VFL) intelligence platform that intercepts live bookmaker WebSocket data (Sportybet / Golden Race, Bet9ja), calculates high-probability betting predictions using machine learning models (Poisson, Elo, Gradient Boosting), stores and tracks best picks in SQLite, automatically settles bet outcomes (Won/Lost) in real time as matches finish, and broadcasts telemetry to remote client apps and Telegram.

### Process Topology (Managed by PM2)
| PM2 ID | Process Name | Entry Point | Role & Description |
|---|---|---|---|
| **3** | `vfl-scraper` | `puppeteer-app/utils/live_companion_sporty.js` | Headless Chrome stealth scraper. Connects to Sportybet Virtuals, intercepts Golden Race WebSocket frames (`/eventBlocks/event/data` & `result`), extracts DOM results, runs ML predictor, writes pending picks to SQLite, and settles completed matches. |
| **6** | `sporty-api` | `puppeteer-app/utils/remote_api_server.js` | High-speed dedicated microservice (Port 4000). Provides read-only REST endpoints, Server-Sent Events (SSE), WebSockets, and diagnostic logs to remote clients with <2ms response time. |
| **1** | `bot-dashboard` | `puppeteer-app/dashboard/` | Electron / React web dashboard (Port 3000) for local desktop monitoring. |
| **4** | `ai-trainer` | `puppeteer-app/utils/auto_trainer_daemon.js` | Background ML auto-trainer daemon for hyperparameter optimization and feature weight calibration. |
| **5** | `google-sync` | `puppeteer-app/utils/google_sync_daemon.js` | Background backup daemon syncing predictions to Google Sheets. |

## 2. Fast Health & Diagnostic Commands

As an AI agent, whenever you inspect or debug this system, run:

```bash
cd /home/ubuntu/Desktop/virtualubuntu/puppeteer-app
npm run health
# OR directly:
node utils/check_health.js
```

### What `npm run health` tells you:
1. **PM2 Process Status**: Checks if `vfl-scraper`, `sporty-api`, etc., are online, memory consumption, CPU, and restart count.
2. **Database Health**:
   - Total bets, Won, Lost, Pending, and Void counts.
   - Win Rate %.
   - Verifies **Zero Voids**.
3. **Pending Bets Audit**:
   - Displays all active pending bets with countdown timers (`in 2m`, `in 5m`).
   - Flags any match overdue by > 5 minutes without a score.
4. **Last 5 Settled Bets**:
   - Shows recent settlements with final scores and outcomes (WON/LOST).
5. **Log File Health**:
   - Displays size of rotating log files (`settlement.log`, `scraper.log`, etc.) and tails the last 3-5 settlement entries.
6. **Overall Verdict**: Returns `🟢 ALL SYSTEMS HEALTHY`, `⚠️ DEGRADED`, or `🚨 UNHEALTHY`.

## 3. Database Architecture & Schema

- **Primary SQLite Database**: `./databases/sportybet_archive.db`
- **Engine**: SQLite in WAL mode (`journal_mode = WAL`) opened with `better-sqlite3`.

### Table: `ai_best_picks_history`
This is the core table tracked by users and remote apps.
```sql
CREATE TABLE ai_best_picks_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    season_name TEXT,             -- e.g. "Sportybet England - Week 17 (2026-09-12 13:34)"
    round_number INTEGER,         -- e.g. 17
    home_team TEXT,               -- e.g. "Arsenal"
    away_team TEXT,               -- e.g. "Chelsea"
    market TEXT,                  -- e.g. "Over 1.5 Goals", "Both Teams to Score", "Away Win"
    probability REAL,             -- Model probability percentage (e.g. 87.5)
    implied_odd REAL,             -- Implied or actual odds (e.g. 1.45)
    displayed_confidence REAL,    -- Confidence score (0 - 100)
    match_time TEXT,              -- HH:MM string (e.g. "13:34")
    kickoff_timestamp INTEGER,    -- UTC epoch ms
    status TEXT DEFAULT 'pending',-- 'pending' | 'won' | 'lost' | 'void'
    actual_score TEXT             -- Final score string (e.g. "2:1")
);
```

### Table: `live_predictions`
Contains all match fixtures generated by the ML engine for current and upcoming rounds before picks are filtered.

### Table: `historical_market_predictions`
Long-term historical archive used by `ai-trainer` to compute Poisson decay weights and calibration matrices.

## 4. How the Settlement Engine Works

1. **Score Ingestion (Dual Path)**:
   - **Path A (Primary)**: WebSocket interception via CDP (Chrome DevTools Protocol) in `live_companion_sporty.js`. When Golden Race pushes `/eventBlocks/event/result`, full-time and half-time scores are parsed.
   - **Path B (Secondary)**: Direct DOM polling of `.history-container .panel` inside the Golden Race iframe every 12 seconds to capture results even if WebSocket drops a frame.
2. **Match Matching (`processResultNow`)**:
   - Matches pending picks in `ai_best_picks_history` where `home_team`, `away_team` match and `kickoff_timestamp` aligns (or within ±180s).
3. **Outcome Evaluation (`evaluatePickOutcome` in `live_companion.js`)**:
   - Parses `ftScore` (e.g. `"3:1"`) and `htScore` (e.g. `"1:0"`).
   - Evaluates markets:
     - `Over 1.5 Goals`: `totalGoals >= 2` ? `won` : `lost`
     - `Over 2.5 Goals`: `totalGoals >= 3` ? `won` : `lost`
     - `Under 2.5 Goals`: `totalGoals <= 2` ? `won` : `lost`
     - `Both Teams to Score`: `homeGoals > 0 && awayGoals > 0` ? `won` : `lost`
     - `Home Win`: `homeGoals > awayGoals` ? `won` : `lost`
     - `Away Win`: `awayGoals > homeGoals` ? `won` : `lost`
     - `Draw`: `homeGoals === awayGoals` ? `won` : `lost`
     - `HT/FT X/1`, `HT/FT 1/1`, `HT/FT 2/2`, etc.: checks both half-time and full-time results.
4. **Direct Update**:
   - Status transitions atomically: `'pending'` ➔ `'won'` OR `'lost'` with `actual_score`.
   - Logged immediately to `logs/settlement.log` via `robust_logger`.

## 5. Structured Rotating Logging (`robust_logger.js`)

Located at: `puppeteer-app/utils/robust_logger.js`

### Log Channels:
- `logs/settlement.log`: Every single match result and bet settlement (WON/LOST/VOID).
- `logs/scraper.log`: Stealth browser actions, iframe recovery, Golden Race navigation, WebSocket frames.
- `logs/ai.log`: ML model inference, weights optimization, calibration parameters.
- `logs/api.log`: Remote microservice requests, queries, connected streaming clients.
- `logs/system.log`: Memory monitoring, watchdog triggers, uncaught exceptions.

### Key Features:
- **Zero Dependencies**: Uses standard Node.js `fs` and `path`.
- **Strict Size Bounds**: Automatically rotates files at **10MB**, keeping a maximum of 3 backups (`.log.1`, `.log.2`, `.log.3`). Strictly prevents disk space exhaustion on the VPS.
- **In-Memory Ring Buffer**: Stores the latest 100 log entries in memory per channel, enabling instantaneous queries over HTTP without touching the disk.

### Usage in Code:
```javascript
const { logger, settlementLogger, scraperLogger, apiLogger } = require('./robust_logger');

// Settle a bet
settlementLogger.settled({
    id: 15568,
    home_team: 'Fulham',
    away_team: 'Arsenal',
    market: 'Over 1.5 Goals',
    actual_score: '1:2',
    status: 'won',
    season_name: 'Sportybet England - Week 17',
    round_number: 17
});

// Log scraper status
scraperLogger.info('Golden Race iframe detected', { league: 'England' });
```

## 7. AI Agent Troubleshooting Runbook

### Case 1: Pending Bets Are Not Settling
1. Run `npm run health`. Check if pending picks are overdue by > 5 minutes.
2. Check `vfl-scraper` status: `pm2 status vfl-scraper`.
3. Check `logs/settlement.log`: `tail -n 30 logs/settlement.log`.
4. If the scraper is stalled or in a 401 loop:
   ```bash
   pm2 restart vfl-scraper
   ```
5. If match scores were missed due to a temporary network blip, run the backfill command:
   ```bash
   node -e "const db = require('better-sqlite3')('databases/sportybet_archive.db'); const { settlePendingAIPicks } = require('./utils/live_companion'); console.log('Settled:', settlePendingAIPicks(db));"
   ```

### Case 2: Stale Phantom Bets or Unwanted Voids
If any retroactive bets or stale voids need cleanup:
```bash
node -e "const db = require('better-sqlite3')('databases/sportybet_archive.db');
db.prepare(\"DELETE FROM ai_best_picks_history WHERE status = 'void'\").run();
console.log('Cleared voids.');"
```

### Case 3: Port 4000 Remote API Unreachable
1. Check process: `pm2 status sporty-api`.
2. Check logs: `tail -n 50 logs/pm2-api-error.log`.
3. Test locally: `curl http://localhost:4000/api/health`.
4. Check firewall: `sudo ufw status` (ensure port 4000/tcp is ALLOW).

## 8. Staking & Bankroll Simulation Engine

Located at: `puppeteer-app/dashboard/src/renderer/src/App.jsx`

The platform features an institutional-grade quantitative simulation engine that calculates realistic equity trajectories, drawdowns, and strategy performance over thousands of historical settled bets in SQLite.

### Multi-Dimensional Filtering Capabilities:
1. **Strategy Type**: Filter across All Strategies, Safest Pick (🛡️), High Value Pick (⚡), or AI Best Pick (🧠).
2. **Market Category**: Filter by any dynamic market in the dataset (Over 1.5, Over 2.5, Under 2.5, Both Teams to Score, 1X2, HT/FT combos) or an aggregate `All Goals Markets` group.
3. **Odds Range**: Numeric Min and Max odds thresholds with preset quick chips (1.2–1.6, 1.6–2.5, 2.5–5.0, 5.0+).
4. **Confidence / Probability**: Filter by ML confidence levels (≥55%, ≥60%, ≥65%, ≥70%, ≥75%, ≥80%, ≥85%).
5. **Time Horizon**: Full History, Today, Last 24 Hours, Last 3 Days, Last 7 Days, or Last N bets (100, 250, 500).
6. **Settlement Outcome**: All outcomes, Won Only (for winning odds distribution), or Lost Only (for loss cluster analysis).
7. **Team Search**: Real-time text search filtering matches involving a specific club (e.g. "Arsenal", "Chelsea").
8. **Round Number Range**: Isolate specific league round windows (e.g. Rounds 10 to 30).
9. **Quick Action Presets**:
   - `🔥 Conf ≥75%`: Immediate filter for high-confidence picks.
   - `⚡ Odds ≥2.0`: Immediate filter for value bets.
   - `🛡️ Safe (1.2-1.6)`: Immediate filter for low-volatility picks.
   - `⚽ Goals Markets`: Immediate filter for goal-line markets.
   - `🔄 Reset`: Restores all filters to full database scope.

### Staking Models Supported:
- **Fixed Flat Stake**: Flat unit allocation per bet (e.g., 100u).
- **% of Initial Capital**: Constant stake proportional to starting bankroll.
- **Dynamic Compounding**: Stakes scale up dynamically with bankroll growth and scale down during drawdowns.
- **Half-Kelly Criterion (50%)**: Mathematical expectation formula scaled by 0.5 to balance growth rate vs volatility.
- **Quarter-Kelly Criterion (25%)**: Conservative fractional Kelly sizing for capital preservation.

### Output Telemetry:
- **10 KPI Performance Cards**: Filtered Bets, Win Rate %, Total Staked, Net Profit/Loss, Final Simulated Balance, ROC %, ROI %, Profit Factor, Max Drawdown (MDD), Max Win/Loss Streaks.
- **Responsive SVG Equity Trajectory**: Real-time vector plotting of the bankroll evolution with baseline, peak, and drawdown area fill.
- **Strategy Breakdown Table**: Per-strategy breakdown with individual win rates, ROI, and simulated capital.
- **Detailed Filtered Bets Audit Table**: Searchable, paginated chronological log with stakes, actual match scores, P/L, and running balance.

## 8b. Edge Gate (profitability safeguard)

Backtests on ~57k settled SportyBet VFL matches (real odds + results, Sep 16 – Oct 2 2026, England league) showed:
every market loses when bet blindly (avg margin ≈ -8.7%; 1X2/OU ≈ -5.3%; HT/FT up to -23%), bookmaker de-vigged
probabilities are essentially perfectly calibrated, and the in-house model has a *worse* Brier score than the bookmaker
in every market (its disagreement with the bookmaker carries no information). Forced picks therefore only pay the margin.

`puppeteer-app/utils/edge_gate.js` publishes a pick only if its market, over the latest settled matches, has
(1) ≥ `edgeGateMinSample` qualifying bets (model prob − de-vigged book prob ≥ `edgeGateMinGap`),
(2) a one-sided ~90% lower confidence bound on ROI > 0, and (3) positive ROI in **both** halves of the window.
It fails closed (unknown market / unverifiable pick = blocked) and re-opens per market automatically if a real edge appears.

- Inspect: `npm run edge:report` (shows per-market n / ROI / lower bound / verdict)
- Tests: `npm run test:edge`
- Disable (legacy always-pick behaviour): set `"strictEdgeGate": false` in `bot_settings.json`
- Tuning keys (optional, in `bot_settings.json`): `edgeGateMinGap`, `edgeGateMinSample`, `edgeGateWindow`, `edgeGateZ`
- Wired in `live_companion.js` → `updateAIPicksHistory` (short-circuit + per-pick gate before insert). Do not bypass it
  by adding new insert paths; do not lower the thresholds to "get picks" — that re-creates the losing behaviour.
